Módulo Avanzado • Data Architecture

Exploring and Extending Shopify’s Data Model

Aprende cómo Shopify modela las transacciones de e-commerce, explora los objetos fundamentales y de nicho (B2B / Retail), y domina la extensión del esquema de datos mediante Metafields y Metaobjects con prácticas reales.

Sección 1: Shopify’s Data Model & Core Ecommerce Concepts

El modelo de datos de Shopify está diseñado para respaldar todo el ciclo de vida de una transacción de comercio unificado. Para entender cómo interactúan los objetos en la base de datos, examinemos las 5 fases del flujo de compra:

1️⃣

1. Navegación en un Canal (Channel)

El cliente explora productos en un canal de venta (Online Store, POS o app móvil). Cada Product posee al menos una Variant por defecto y puede agruparse en Collections para facilitar el merchandising.

2️⃣

2. Carrito de Compras (Cart)

El carrito es específico del canal. En la tienda online se compone de Cart Line Items que registran la cantidad de cada variante, calculando el subtotal antes de impuestos, envíos o descuentos.

3️⃣

3. Inicio de Checkout

Flujo optimizado de 1 a 3 páginas donde el comprador ingresa su dirección de envío, método de despacho y cupones de descuento.

4️⃣

4. Pago y Creación de la Orden (Order)

La captura exitosa del pago crea la entidad Order y genera las páginas de confirmación (Thank You Page y Order Status Page) con número de pedido y fecha estimada de entrega.

5️⃣

5. Fulfillment y Despacho

La tienda prepara los productos para despacho. El inventario se actualiza automáticamente en tiempo real a través de todas las ubicaciones físicas (Locations) y se genera el código de seguimiento para el cliente.

Objetos Fundamentales de E-Commerce en Shopify

Objeto Descripción del Objeto Recursos Conectados en el Modelo
Products Artículos individuales o digitales disponibles para la venta. Collections, Locations, ProductVariants
Collections Agrupaciones de productos para navegación y merchandising. Products
Customers Compradores registrados o que realizaron pedidos. Orders, Gift cards, Companies

Orders Transacciones completadas con detalles de productos y pagos. Products, Locations, Customers, Markets, Companies

Fulfillment orders Tareas y etapas necesarias para empaquetar y despachar partes de una orden. Orders, FulfillmentServices
Fulfillment services Proveedores logísticos externos (3PL) para almacenamiento y envío. Products, FulfillmentOrders
Gift cards Emisión y canje de crédito de tienda en formato de tarjetas de regalo. Customers, Orders
Selling plan Configuraciones predefinidas de compra: suscripciones, preventas o cuotas. Products, SellingPlanGroups

Objetos de Nicho para B2B y Retail

Para clientes con requerimientos corporativos (B2B) o tiendas físicas con retiro en sucursal (Retail), Shopify dispone de objetos especializados en Liquid y GraphQL:

  • customer.b2b?: Booleano que valida si el cliente actual pertenece a una empresa B2B aprobada.
  • customer.company_available_locations: Lista de sucursales autorizadas de la empresa compradora.
  • customer.current_company: Empresa B2B activa durante la sesión del comprador.
  • store_availability: Objeto que consulta el inventario local para retiro en tienda física (Pickup in store).

Sección 3: Building Custom Data Objects (Metafields & Metaobjects)

Cuando los clientes demandan desplegar información especializada (guías de cuidado de plantas vivas, tablas de medidas de modelos, o certificaciones ecológicas), los Metafields y Metaobjects permiten extender el esquema relacional nativo sin requerir un CMS externo ni apps pesadas.

✨

Mayor Personalización & UX

Permite enriquecer las fichas de producto con información visualmente estructurada y relevante para aumentar la conversión.

🧩

Funcionalidad Extendida

Admite propiedades complejas como selectores de color hexadecimal, descargas de PDFs e integración con ERPs para lead times.

🔄

Disponibilidad Omnicanal

Accesibles tanto en el frontend (Liquid y Storefront API) como en el backend mediante la GraphQL Admin API para sincronización bidireccional.

Anatomía de los Metafields

Componente Propósito Ejemplo
Namespace Contenedor o categoría para agrupar campos con funciones similares. custom, specs, seo, model
Key Nombre identificador único del campo dentro del namespace. wearing_size, battery_life, care_pdf
Value El dato persistido fuertemente tipado. "Talla M", 14, #16a34a, referencia GID
🏷️

Tipos de Datos Estándar Soportados en Metafields

Color picker (swatches), Measurement (longitud, peso, ancho de manga), Reference (size charts, bundles, productos recomendados, metaobjects), Date & Time, Money, Text (single/multi-line), File (PDFs, imágenes en CDN), Number (integer/decimal), True/False (switches booleanos), JSON, Rating (estrellas/reseñas) y URL.

¿Qué son los Metaobjects?

Un Metaobject es una entidad de datos completa compuesta por múltiples campos estructurados. Posee dos elementos esenciales:

  • Definition (Definición): El esquema que declara la estructura (ej. Model Info con campos nombre, estatura, busto, cintura, caderas).
  • Entries (Entradas): Los registros o filas individuales de datos cargados (ej. Entrada para Jasmine, Entrada para Shakira).

Sección 5: Lab: Building Custom Data Objects (Model Info para Lily)

📏

Escenario de Cliente: Medidas de Modelos y Tallas en "Stylish Stitches"

Lily desea que su marca apele a todas las complexiones físicas y contrata a dos modelos con medidas corporales diferentes (*Jasmine* y *Shakira*) para su campaña de moda. En cada ficha de producto (PDP), Lily desea mostrar las medidas exactas de la modelo que viste la prenda y la talla correspondiente que lleva puesta.

Nombre de Modelo Estatura (Height) Busto (Bust) Cintura (Waist) Caderas (Hips)
Jasmine 165 cm (5 ft) 84 cm (33 in) 66 cm (26 in) 91 cm (36 in)
Shakira 183 cm (6 ft) 112 cm (44 in) 76 cm (37 in) 122 cm (48 in)
1

Paso 1: Crear Metafield para la Talla que Viste la Modelo (Wearing Size)

En el Shopify Admin, navega a Settings > Custom data > Products > Add definition:

  • Name: Wearing Size
  • Namespace and key: model.wearing_size
  • Description: Talla de la prenda que la modelo viste en la campaña
  • Type: Single line text
2

Paso 2: Crear Definición de Metaobject Model Info

En Settings > Custom data > Metaobjects > Add definition (o en Content > Metaobjects):

  • Name: Model Info
  • Type: model_info
  • Campos a incorporar:
    • name (Tipo: Single line text)
    • height (Tipo: Dimension)
    • bust (Tipo: Dimension)
    • waist (Tipo: Dimension)
    • hips (Tipo: Dimension)
3

Paso 3: Crear las Entradas (Entries) para Jasmine y Shakira

Ve a Content > Metaobjects > Model Info > Add entry:

  1. Crea la entrada para Jasmine con sus medidas (165 cm, Busto 84 cm, Cintura 66 cm, Caderas 91 cm) y guarda.
  2. Crea la entrada para Shakira con sus medidas (183 cm, Busto 112 cm, Cintura 76 cm, Caderas 122 cm) y guarda.
4

Paso 4: Crear Metafield de Referencia a Metaobject en Productos

En Settings > Custom data > Products > Add definition:

  • Name: Model Info
  • Namespace and key: models.model_info
  • Type: Metaobject Reference > Selecciona Model Info (1 entrada).
5

Paso 5: Asignar Datos en las Fichas de Producto

Abre un producto en el Admin (ej. "Classic varsity top") y en la sección inferior de Metafields selecciona a Jasmine en models.model_info y escribe Talla S en model.wearing_size.

6

Paso 6: Vincular en el Theme Editor con Dynamic Sources

Abre Online Store > Themes > Customize y navega a la plantilla de producto:

  1. En la sección Product information, agrega un bloque Collapsible Row (Fila desplegable).
  2. Título del bloque: Medidas de la Modelo & Guía de Talla.
  3. En el contenido de la fila, haz clic en el icono de Dynamic Source (Fuente dinámica) y vincula los campos de Product > models.model_info y model.wearing_size.
  4. Guarda y previsualiza en el Storefront.
