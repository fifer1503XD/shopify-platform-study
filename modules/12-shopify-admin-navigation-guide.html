Módulo 12 • Operaciones & Back-Office

12. Lo que un Dev debe conocer del Shopify Admin

El Shopify Admin no es solo una interfaz para el comerciante; es la fuente de verdad de la arquitectura de datos, el motor de reglas de negocio y el límite de lo que podemos extender mediante código. Como desarrollador o arquitecto, cada área del panel de administración impacta directamente en cómo construyes el frontend en Liquid, qué APIs consumes y cómo diseñas integraciones backend.

1. Matriz: Lo que un Dev debe conocer del Admin

Esta matriz resume las 8 áreas fundamentales del back-office de Shopify, qué representan a nivel de datos y por qué son críticas para el desarrollo:

Área Qué es Por qué te importa (Impacto Dev)
Productos y variantes Opciones, SKU, precio, imágenes, código de barras y estado. Base de PDP, cards y búsqueda: Es el modelo de datos que alimenta las fichas de producto, selectores de variantes, precios dinámicos y snippets de catálogo.
Colecciones Manuales o automáticas por reglas lógicas de tags, tipo o precio. Son las PLP y los filtros: Estructuran las rutas de catálogo (/collections/{handle}), la paginación Liquid y la taxonomía de navegación.
Inventario Stock por ubicación física (Locations), transferencias y estados. Disponibilidad y retiro en tienda (BOPIS): Alimenta la verificación de stock en tiempo real en la PDP y el selector de sucursales para Store Pickup.
Pedidos y clientes Órdenes, estados de pago/envío, cuentas y clientes B2B. Webhooks e integraciones ERP: Dispara eventos en tiempo real (orders/create, fulfillments) para conectar con SAP, NetSuite o CRMs externos.
Descuentos Códigos promocionales y descuentos automáticos por carrito. Lógica custom con Shopify Functions: Permite programar reglas complejas de precios (2x1 escalonados, bundle discounts) en WebAssembly sin latencia.
Contenido Metaobjetos, páginas institucionales, menús y archivos CDN. Datos estructurados para el theme: Expone entidades relacionales en Liquid (shop.metaobjects) para lookbooks, tablas de tallas y diseñadores.
Tienda online Themes, Theme Editor visual, páginas, navegación y preferencias. Donde vive tu código Liquid: El entorno de plantillas JSON, secciones modulares, snippets atómicos y assets de JavaScript/CSS.
Configuración Checkout, pasarelas de pago, zonas de envío, apps e impuestos. Límites de lo que puedes cambiar: Conocer las restricciones de la plataforma (Checkout Extensibility vs Checkout.liquid cerrado, OAuth scopes y pasarelas).

2. Inventario Multialmacén & Retiro en Tienda (Store Pickup / BOPIS)

Shopify normaliza el inventario separando el producto de sus ubicaciones físicas. Cada punto de venta o almacén es una entidad Location, y el stock de cada variante se rastrea mediante InventoryLevel.

📦

Implementación de Disponibilidad de Retiro en Tienda en Liquid (`store-availability.liquid`)

Shopify ofrece un objeto nativo en Liquid llamado variant.store_availabilities que permite renderizar si el producto seleccionado está disponible para recogida inmediata en sucursales cercanas:

snippets/pickup-availability.liquid 
{%- assign pick_up_availabilities = product.selected_or_first_available_variant.store_availabilities | where: 'pick_up_enabled', true -%}

<div class="pickup-availability-container">
  {%- if pick_up_availabilities.size > 0 -%}
    <div class="pickup-header">
      <span class="pickup-icon">🏬</span>
      <div>
        <p class="pickup-title">Disponible para retiro en tienda hoy</p>
        <p class="pickup-subtitle">Normalmente listo en 2 horas</p>
      </div>
    </div>

    <ul class="pickup-stores-list">
      {%- for availability in pick_up_availabilities -%}
        <li class="store-item">
          <strong>{{ availability.location.name }}</strong>
          <span class="{% if availability.available %}in-stock{% else %}out-stock{% endif %}">
            {% if availability.available %}✓ Stock disponible{% else %}✕ No disponible en esta sede{% endif %}
          </span>
          <span class="store-address">{{ availability.location.address.city }}, {{ availability.location.address.country }}</span>
        </li>
      {%- endfor -%}
    </ul>
  {%- endif -%}
</div>

3. Pedidos, Clientes y Arquitectura de Webhooks para Integraciones ERP

Cuando una tienda escala, el procesamiento de pedidos y la actualización de clientes se delega a sistemas externos (SAP, NetSuite, Salesforce). Los desarrolladores deben diseñar consumidores de Webhooks idempotentes para evitar procesar órdenes duplicadas.

Tópico de Webhook Momento de Disparo Payload Clave & Acción en ERP
orders/paid Cuando la pasarela confirma el pago del checkout. Generar factura fiscal, decrementar stock contable y reservar líneas de producto.
orders/fulfilled Cuando el operador logístico asigna número de guía (tracking). Notificar al cliente vía SMS/WhatsApp y sincronizar estado en el sistema de transporte.
customers/create Registro de un nuevo comprador en la tienda. Crear registro en CRM (HubSpot/Klaviyo) y asociar programa de lealtad.
refunds/create Devolución parcial o total ejecutada en el Admin. Emitir nota de crédito contable y ajustar inventario retornado.

4. Descuentos y Lógica Personalizada con Shopify Functions

Shopify permite crear descuentos mediante el Admin (códigos y reglas estándar) o mediante Shopify Functions (código compilado a WebAssembly que corre en los servidores de Shopify durante el checkout en menos de 5ms):

Admin Discounts vs Shopify Functions

Mientras que los descuentos del admin se limitan a combinaciones sencillas (monto fijo, porcentaje, 2x1), Shopify Functions (Discount API & Cart Transform API) te permite programar:

  • Descuentos escalonados por nivel de lealtad almacenado en un Metafield del cliente.
  • Empaquetado dinámico de productos (Bundles personalizados) que descuentan ítems individuales en inventario.
  • Reordenamiento o renombrado de métodos de pago y tarifas de envío en tiempo real según el código postal.

5. Configuración del Admin y Límites de lo que un Dev Puede Modificar

En la sección Settings (Configuración) residen las restricciones de infraestructura y seguridad de Shopify:

Configuración Qué controla Límites y Reglas de Desarrollo
Checkout Páginas de pago, información de contacto, propinas y direcciones. Checkout Extensibility: En tiendas Plus ya no se edita checkout.liquid. Toda personalización se realiza con Checkout UI Extensions en React/TypeScript dentro de un sandbox seguro. En planes estándar, solo se edita branding (colores y logo).
Payments (Pasarelas) Shopify Payments, Mercado Pago, Stripe, PayPal y medios manuales. No puedes inyectar scripts personalizados en los campos de tarjeta de crédito (cumplimiento estricto PCI-DSS Nivel 1). Los pagos externos deben procesarse mediante Hosted Payment SDK o Payment Customization Functions.
Shipping & Delivery Zonas de envío, tarifas fijas, cálculo por transportadora (Carrier Service). Para cálculo dinámico en tiempo real se debe implementar una CarrierService API o una Function de Delivery Customization.
Apps & Sales Channels Permisos de API (Scopes) y credenciales de Custom Apps. Toda app debe declarar estrictamente los scopes requeridos (ej. read_products, write_orders) y gestionar el token de forma segura sin exponerlo en el frontend.

Orders (Gestión de Pedidos)

Core Operations

Control central de las transacciones generadas en la tienda. Permite procesar envíos (fulfillment), gestionar devoluciones, emitir reembolsos parciales o totales y recuperar carritos abandonados.

Subsecciones y Vistas Internas:
  • All Orders: Listado completo con filtros por estado de pago (Paid, Pending) y cumplimiento (Fulfilled, Unfulfilled).
  • Draft Orders: Pedidos manuales creados por el merchant (ej: ventas telefónicas o cotizaciones B2B).
  • Abandoned Checkouts: Sesiones donde el cliente inició el checkout pero no completó el pago.
Entidades GraphQL / REST:
Order, DraftOrder, FulfillmentOrder, Refund
Rol del Desarrollador:
Configurar Webhooks (orders/create, orders/fulfilled), integrar con ERPs y automatizar fulfillments con 3PLs.
Ejemplo de Consulta GraphQL Admin API 
query GetRecentOrders {
  orders(first: 10, sortKey: CREATED_AT, reverse: true) {
    edges {
      node {
        id
        name
        createdAt
        displayFinancialStatus
        displayFulfillmentStatus
        totalPriceSet {
          shopMoney {
            amount
            currencyCode
          }
        }
      }
    }
  }
}
