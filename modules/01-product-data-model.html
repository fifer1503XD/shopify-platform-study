Módulo 01

1. Modelo de Datos de Productos en Shopify

Antes de escribir una sola línea de Liquid o realizar llamadas a la Admin API, es imprescindible comprender cómo Shopify normaliza y almacena sus entidades de catálogo en su base de datos relacional subyacente.

Arquitectura del Producto: Products vs. Variants

En Shopify, la entidad Product no es un artículo vendible directamente por sí mismo en el checkout; actúa como un contenedor padre o paraguas conceptual que agrupa metadatos globales (título, descripción HTML, proveedor, tipo de producto, etiquetas y lista de imágenes generales).

La entidad ProductVariant representa la unidad de inventario comercializable real (relación 1 a N). Cada variante posee su propio precio, precio de comparación (compare_at_price), SKU, código de barras (barcode), peso físico y puntero directo al inventario.

Estructura Relacional del Catálogo (1:N)
Product (Contenedor Padre) Entidad Global
  • id: ID (GID)
  • title: String
  • handle: String (Slug URL)
  • vendor: String
  • options: Array<ProductOption>
  • media: Array<Media>
ProductVariant (Item Vendible en Checkout) 1 a N Variantes
  • id: ID (GID)
  • sku: String
  • price: Money
  • inventory_item_id: ID
  • selected_options: [ {name, value} ]
  • requires_shipping: Boolean

Opciones y Valores (Options & Values)

Las opciones definen las dimensiones de variación del producto (por ejemplo: Talla, Color, Material). En Liquid se accede mediante el objeto iterativo product.options_with_values.

⚠️

Restricción Nativa: 3 Opciones / 100 Variantes

Shopify impone un límite estricto de máximo 3 opciones por producto y un total combinado de 100 variantes (ej: 4 tallas x 5 colores x 6 materiales = 120 combinaciones, lo cual excedería el límite). Solución de Arquitectura: Para catálogos complejos, se implementa arquitectura de "Productos Vinculados" (Linked Products) conectados vía Metafields de referencia, o personalizaciones vía Line Item Properties.

Liquid snippets/product-option-selector.liquid 
{% comment %} Renderizado de opciones y valores con control de estado {% endcomment %}
<div class="product-form-options">
  {% for option in product.options_with_values %}
    <fieldset class="option-fieldset">
      <legend class="option-name">{{ option.name }}: <span class="selected-value">{{ option.selected_value }}</span></legend>
      <div class="option-values-list">
        {% for value in option.values %}
          <label class="option-pill {% if option.selected_value == value %}is-active{% endif %}">
            <input 
              type="radio" 
              name="option-{{ option.name | handleize }}" 
              value="{{ value | escape }}"
              {% if option.selected_value == value %}checked{% endif %}
              data-option-position="{{ option.position }}"
            >
            <span>{{ value }}</span>
          </label>
        {% endfor %}
      </div>
    </fieldset>
  {% endfor %}
</div>

Colecciones: Manuales vs. Automatizadas (Smart Collections)

Característica Colecciones Manuales (CustomCollections) Colecciones Automatizadas (SmartCollections)
Mecanismo de Inclusión Asignación estática 1 por 1 por el administrador. Reglas dinámicas booleanas (AND / OR).
Condiciones Soportadas No aplica (lista explícita). Tags, Product Type, Vendor, Price, Compare Price, Inventory Stock.
Mantenimiento Operativo Alto. Requiere intervención manual con nuevos SKUs. Bajo / Automático en tiempo real al indexar productos.
Uso Recomendado Curaduría editorial, promociones especiales, lookbooks. Catálogos masivos por categorías, marcas o estado de inventario.

Creación de Productos vía Código: GraphQL vs. REST Admin API

Shopify recomienda GraphQL Admin API como estándar exclusivo para desarrollos modernos debido al costo de consulta medido por complejidad (query cost) en lugar de rate limits ciegos, y a la capacidad de crear productos y variantes anidadas en un solo llamado atómico.

GraphQL mutations/productCreate.graphql 
# Creación atómica de Producto con Variantes, SKU e Inventario
mutation CreateCompleteProduct($input: ProductInput!) {
  productCreate(input: $input) {
    product {
      id
      title
      handle
      status
      variants(first: 5) {
        nodes {
          id
          sku
          price
          inventoryItem {
            id
            tracked
          }
        }
      }
    }
    userErrors {
      field
      message
    }
  }
}

# Ajuste de niveles de stock en ubicación específica (InventoryLevel)
mutation AdjustStock($input: InventoryAdjustQuantitiesInput!) {
  inventoryAdjustQuantities(input: $input) {
    inventoryAdjustmentGroup {
      createdAt
      reason
      changes {
        name
        delta
        quantityAfterChange
      }
    }
    userErrors {

Importación y Exportación Masiva vía CSV

Para cargas masivas y migraciones de catálogo, el archivo CSV nativo de Shopify requiere una estructura de columnas estrictamente normalizada. La columna Handle actúa como clave de agrupación: múltiples filas con el mismo handle representan las variantes de un único producto.
