15. Cómo funciona el Shopify CLI: Arquitectura & Flujos de Trabajo

El Shopify CLI (Command-Line Interface) es la herramienta fundamental en el cinturón de cualquier desarrollador profesional de Shopify. No es un simple script de subida de archivos; es un entorno orquestador que crea servidores de desarrollo locales con Hot Reload, gestiona temas efímeros en la nube, audita la calidad del código Liquid en tiempo real mediante linters, sincroniza cambios con el Theme Editor y permite construir aplicaciones y extensiones modernas basadas en WebAssembly y React.

1. Arquitectura Interna: ¿Qué ocurre bajo el capó?

Cuando ejecutas un comando como shopify theme dev, el CLI no interpreta el Liquid en tu computadora (porque el motor Liquid y la base de datos de productos viven en la infraestructura distribuida de Shopify). En su lugar, orquesta una arquitectura híbrida:

⚡ 1. Servidor Proxy Local & Hot Reload

El CLI levanta un servidor local (típicamente en http://127.0.0.1:9292). Al navegar en esta URL, el proxy consulta la tienda real en la nube, pero inyecta en milisegundos tus archivos locales de Liquid, CSS y JavaScript modificados.

☁️ 2. Development Theme (Tema Efímero Oculto)

Shopify crea automáticamente un tema privado y temporal en tu tienda de desarrollo denominado "Development (hash)". Este tema no es visible para los clientes y se vincula únicamente a tu sesión de terminal activa.

🔄 3. Sincronización Bidireccional del Theme Editor

El CLI genera un enlace directo al Theme Editor de tu tema de desarrollo. Si un diseñador modifica una configuración visual o un bloque en el navegador, el archivo templates/*.json o config/settings_data.json se descarga automáticamente a tu disco local.

🔒 4. Autenticación Segura (OAuth / Headless Tokens)

Utiliza un flujo de autenticación seguro basado en navegador con tu cuenta de Shopify Partners o Shopify ID. Genera tokens de sesión efímeros que se refrescan en segundo plano sin exponer API Keys en texto plano.

2. Matriz de Comandos Esenciales para Desarrollo de Temas

Estos son los comandos principales que utilizarás a diario al construir y desplegar temas:

Comando Qué hace Flags Clave & Buenas Prácticas
shopify theme dev Inicia el servidor local, sincroniza archivos con el tema de desarrollo efímero y habilita recarga en vivo (Live Reload). --store=tienda.myshopify.com
--theme-editor-sync
shopify theme check Ejecuta el linter estático oficial de Liquid. Detecta errores de sintaxis, objetos obsoletos, problemas de accesibilidad y schemas JSON inválidos. --auto-correct
--category=performance
shopify theme pull Descarga los archivos de un tema remoto a tu directorio local de trabajo. --live (baja el tema publicado)
--theme=12345678
shopify theme push Sube tu código local a un tema específico en la tienda. --unpublished (crea nuevo tema sin publicar)
--live ⚠️ (¡Cuidado: sobreescribe prod!)
shopify theme publish Publica un tema inédito (*unpublished*) convirtiéndolo en el tema principal visible en vivo para los compradores. --theme=12345678
shopify theme package Empaqueta el tema en un archivo .zip optimizado y validado, listo para subir manualmente o distribuir en el Theme Store. Valida automáticamente con Theme Check antes de empaquetar.

3. Shopify Theme Check: Linters & Análisis Estático

Theme Check viene integrado de forma nativa en el CLI. Analiza el código antes de que llegue a producción y previene caídas catastróficas del storefront:

CONFIGURACIÓN: .theme-check.yml 
# .theme-check.yml - Reglas de Calidad para el Tema
extends: theme-check:recommended

# Regla de rendimiento: Evitar el tag obsoleto {% include %}
DeprecatedTag:
  enabled: true
  severity: error

# Regla de schemas JSON: Validar que todos los presets y settings tengan traducción o formato correcto
ValidSchema:
  enabled: true
  severity: error

# Regla de accesibilidad: Obligar atributos alt en tags de imagen
ImgLazyLoading:
  enabled: true
  severity: suggestion

# Desactivar advertencias específicas si se requiere
ParserBlockingScript:
  enabled: true
  severity: warning
