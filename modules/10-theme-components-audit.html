10. Anatomía y Auditoría de Componentes en un Tema Shopify

Antes de modificar, refactorizar o construir sobre un tema existente de Shopify (como Dawn, Horizon o un tema a medida), un desarrollador senior debe saber auditar qué componentes existen, cómo se comunican entre sí y dónde residen las fuentes de verdad. En este módulo aprenderás a mapear la estructura completa de un tema Online Store 2.0, inspeccionar dependencias entre secciones y snippets, diagnosticar deuda técnica con Shopify CLI y optimizar la carga del árbol de renderizado.

1. Anatomía Estructural de un Tema en Shopify Online Store 2.0

Un tema de Shopify consta estrictamente de 7 directorios raíz obligatorios. Cada uno cumple una función específica dentro del ciclo de vida del renderizado:

Directorio Archivos Típicos Responsabilidad & Ciclo de Vida
layout/ theme.liquid, password.liquid El contenedor HTML global (<head>, scripts principales, <body>). Inyecta obligatoriamente {{ content_for_header }} en el head y {{ content_for_layout }} en el body.
templates/ index.json, product.json, collection.json, cart.json Plantillas JSON que definen qué secciones y en qué orden se renderizan en cada tipo de página. También almacenan los settings específicos de cada sección en esa página.
sections/ header.liquid, main-product.liquid, footer.liquid Componentes de bloque autónomos. Poseen su propio {% schema %} con configuración editable desde el Theme Editor, soporte para bloques reordenables (blocks) y presets.
snippets/ card-product.liquid, price.liquid, icon-cart.liquid Componentes atómicos reutilizables sin schema propio. Se invocan mediante {% render 'nombre-snippet', prop: valor %} con un scope de variables aislado.
assets/ theme.js, base.css, product-form.js Archivos estáticos (JavaScript, CSS, imágenes, SVG, fuentes). Se cargan en el frontend mediante el filtro de Liquid {{ 'archivo.js' | asset_url | script_tag }}.
config/ settings_schema.json, settings_data.json settings_schema.json define el panel de configuración global del tema (colores, tipografía, redes sociales). settings_data.json almacena los valores reales guardados por el comerciante.
locales/ es.json, en.default.json Archivos de traducción para internacionalización (i18n). Sus cadenas se consumen en Liquid con el filtro {{ 'general.cart.title' | t }}.

2. Herramientas de Auditoría e Inspección Técnica

A

Shopify Theme Check (Linter Oficial en CLI)

Theme Check es el analizador estático oficial de Shopify para Liquid y JSON. Detecta errores de sintaxis, violaciones de rendimiento, snippets no referenciados (código muerto) y llamadas deprecadas a {% include %}:

Terminal: Ejecutar Auditoría Estática de Tema 
# Ejecutar análisis estático en la raíz del tema
shopify theme check

# Ejecutar con corrección automática de errores detectables
shopify theme check --auto-correct

# Analizar rendimiento de Liquid específicamente
shopify theme check --category liquid,performance
B

Shopify Theme Inspector for Chrome (Flamegraphs de Liquid)

Extensión oficial para DevTools que mide el tiempo de ejecución en milisegundos que tarda cada sección y snippet en renderizarse en los servidores de Shopify antes de enviar el HTML al navegador:

  • Permite identificar cuellos de botella en bucles Liquid complejos (ej: bucles anidados sobre colecciones o variantes).
  • Muestra un gráfico de cascada (flamegraph) separando el tiempo de procesamiento por archivo.
C

Inspección del DOM y Marcadores de Sección

Cada sección renderizada por Shopify se envuelve en el navegador con un elemento <div id="shopify-section-[section_id]" class="shopify-section">. Esto permite abrir el inspector de elementos (F12) y rastrear instantáneamente qué archivo en la carpeta sections/ generó cada parte del sitio.

3. Secciones vs. Snippets: Reglas de Decisión Arquitectónica

Criterio Sections (sections/*.liquid) Snippets (snippets/*.liquid)
Schema Editable Sí: Contiene tag {% schema %} con controles para el Theme Editor. No: No puede tener schema propio. Recibe parámetros vía {% render %}.
Ámbito de Variables Tiene acceso al objeto global del template y sus propios section.settings. Aislado: No hereda variables locales salvo que se pasen explícitamente como argumentos.
Invocación Vía Template JSON o mediante {% section 'header' %}. Vía {% render 'card-product', product: item %}.
Uso recomendado Estructuras de layout completas, banners, grids, formularios principales. Microcomponentes reutilizables: botones, íconos, precios, badges, tarjetas.
Por qué `{% include %}` está PROHIBIDO en Temas Modernos

El tag antiguo {% include %} introducía variables en el scope global del padre, provocando colisiones de nombres de variables difíciles de depurar y degradando el rendimiento porque el compilador de Liquid no podía optimizar el AST (Abstract Syntax Tree). El tag moderno {% render %} aísla completamente el contexto, permitiendo compilación en paralelo y optimizaciones de caché en los edge servers de Shopify.
