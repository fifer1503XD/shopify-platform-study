1. Modelo de Datos de Productos en Shopify

Antes de escribir una sola línea de Liquid o realizar llamadas a la Admin API, es imprescindible comprender cómo Shopify normaliza y almacena sus entidades de catálogo en su base de datos relacional subyacente.

Arquitectura del Producto: Products vs. Variants

En Shopify, la entidad Product no es un artículo vendible directamente por sí mismo en el checkout; actúa como un contenedor padre o paraguas conceptual que agrupa metadatos globales (título, descripción HTML, proveedor, tipo de producto, etiquetas y lista de imágenes generales).

La entidad ProductVariant representa la unidad de inventario comercializable real (relación 1 a N). Cada variante posee su propio precio, precio de comparación (compare_at_price), SKU, código de barras (barcode), peso físico y puntero directo al inventario.

Estructura Relacional del Catálogo (1:N)
Product (Contenedor Padre) Entidad Global
  • id: ID (GID)
  • title: String
  • handle: String (Slug URL)
  • vendor: String
  • options: Array<ProductOption>
  • media: Array<Media>
ProductVariant (Item Vendible en Checkout) 1 a N Variantes
  • id: ID (GID)
  • sku: String
  • price: Money
  • inventory_item_id: ID
  • selected_options: [ {name, value} ]
  • requires_shipping: Boolean

Opciones y Valores (Options & Values)

Las opciones definen las dimensiones de variación del producto (por ejemplo: Talla, Color, Material). En Liquid se accede mediante el objeto iterativo product.options_with_values.

⚠️

Restricción Nativa: 3 Opciones / 100 Variantes

Shopify impone un límite estricto de máximo 3 opciones por producto y un total combinado de 100 variantes (ej: 4 tallas x 5 colores x 6 materiales = 120 combinaciones, lo cual excedería el límite). Solución de Arquitectura: Para catálogos complejos, se implementa arquitectura de "Productos Vinculados" (Linked Products) conectados vía Metafields de referencia, o personalizaciones vía Line Item Properties.

Colecciones: Manuales vs. Automatizadas (Smart Collections)

Característica Colecciones Manuales (CustomCollections) Colecciones Automatizadas (SmartCollections)
Mecanismo de Inclusión Asignación estática 1 por 1 por el administrador. Reglas dinámicas booleanas (AND / OR).
Condiciones Soportadas No aplica (lista explícita). Tags, Product Type, Vendor, Price, Compare Price, Inventory Stock.
Mantenimiento Operativo Alto. Requiere intervención manual con nuevos SKUs. Bajo / Automático en tiempo real al indexar productos.
Uso Recomendado Curaduría editorial, promociones especiales, lookbooks. Catálogos masivos por categorías, marcas o estado de inventario.

2. Dominio Total de Metafields y Metaobjects

Los Metafields permiten extender el esquema de datos nativo asociando pares clave-valor fuertemente tipados a productos, variantes, clientes o pedidos. Los Metaobjects son entidades completas y reutilizables compuestas por múltiples campos, equivalentes a tablas relacionales personalizadas en Shopify.

Tipos de Datos en Metafields

📄

Texto y Primitivos

single_line_text_field, multi_line_text_field, number_integer, number_decimal, boolean, date y color.

🔗

Referencias (References)

file_reference (PDFs, videos, imágenes en CDN), product_reference, page_reference y metaobject_reference.

📚

Listas (Lists)

Array tipado: list.single_line_text_field o list.file_reference para galerías de demostración y listas de características.

⚙️

Estructuras JSON

json: Permite persistir estructuras anidadas arbitrarias cuando se requiere flexibilidad no soportada por tipos estándar.

Metafields en Liquid: Sintaxis y Filtros

En Liquid, el acceso canónico se realiza a través de la notación de objeto {{ resource.metafields.namespace.key.value }}. Regla de oro: Siempre incluir la propiedad .value para desempaquetar el objeto tipado subyacente.

3. Filtrado y Búsqueda con Datos Personalizados

Las tiendas enterprise demandan sistemas de filtrado por facetas (Facet Filtering) avanzados, como filtrar colecciones por rango de frecuencia, tipo de material o compatibilidad, alimentados directamente por Metafields.

Shopify Search & Discovery App

La aplicación oficial Shopify Search & Discovery permite activar filtros nativos basados en:

  • Disponibilidad de stock (`filter.v.availability`).
  • Rango de precios (`filter.v.price.gte` / `filter.v.price.lte`).
  • Opciones de producto (`filter.v.option.color`).
  • Metafields personalizados (`filter.p.m.custom.material` o `filter.p.m.custom.connectivity`).

Storefront Filtering API & AJAX Rendering

Para crear una experiencia de filtrado instantánea sin recargar la página completa, consumimos la Shopify Section Rendering API pasando los parámetros de filtro mediante JavaScript (Fetch).

JavaScript (ES6+) assets/collection-filters.js 
// Implementación de Facet Filter reactivo con Section Rendering API
class CollectionFilters {
  constructor(formElement, gridContainerId) {
    this.form = formElement;
    this.gridContainer = document.getElementById(gridContainerId);
    this.bindEvents();
  }

  bindEvents() {
    this.form.addEventListener('change', () => this.applyFilters());
  }

  async applyFilters() {
    const formData = new FormData(this.form);
    const params = new URLSearchParams(formData);
    
    // Indicamos a Shopify que solo re-renderice la sección de grilla de productos
    params.set('section_id', 'main-collection-product-grid');
    
    // Actualizamos URL en el navegador sin recargar
    window.history.pushState({}, '', `${window.location.pathname}?${params.toString()}`);

    try {
      this.gridContainer.classList.add('is-loading');
      
      const response = await fetch(`${window.location.pathname}?${params.toString()}`);
      const htmlText = await response.text();
      
      const parser = new DOMParser();
      const doc = parser.parseFromString(htmlText, 'text/html');
      const newGridContent = doc.getElementById('main-collection-product-grid');

      if (newGridContent) {
        this.gridContainer.innerHTML = newGridContent.innerHTML;
      }
    } catch (error) {
      console.error('Error al aplicar filtros de colección:', error);
    } finally {
      this.gridContainer.classList.remove('is-loading');
    }
  }
}

Lab: Build a dev store with product data and simulate a transaction

Construcción de una tienda de desarrollo para indumentaria ("Stylish Stitches"), exploración del Shopify Admin, importación masiva de catálogo y simulación de transacciones con pasarela de prueba.

👗

Escenario de Cliente: "Stylish Stitches"

Un negocio de indumentaria y moda de autor llamado "Stylish Stitches", propiedad de la diseñadora Lily, está iniciando su transformación digital para expandir su alcance mediante una tienda online en Shopify. Ante el desafío de llevar sus prendas de alta confección al mundo virtual, Lily recurre a vos para construir y configurar su tienda desde las bases.

Nota de arquitectura: Nunca utilices una tienda real de producción para estas actividades prácticas. Crearemos una Development Store (Tienda de Desarrollo) en Shopify Partners para ejecutar personalizaciones de tema, scripts Liquid y pruebas backend sin costos ni riesgos.

1

Paso 1: Registro en Shopify Partners y Creación de la Tienda de Desarrollo

Sigue estos pasos en el portal de partners de Shopify:

  1. Crea una cuenta en Shopify Partners (si aún no posees una).
  2. Haz clic en tu nombre en la esquina superior derecha y selecciona Dev Dashboard.
  3. En el menú lateral izquierdo, haz clic en Dev stores (Tiendas de desarrollo).
  4. Haz clic en el botón Create dev store (Crear tienda de desarrollo).
  5. Asigna un nombre a tu tienda (por ejemplo: stylish-stitches-lab) y selecciona el propósito de la tienda (Build a new store for a client).
  6. IMPORTANTE: No selecciones "Generate test data for store". Dejaremos la tienda limpia para importar nuestro propio catálogo de indumentaria en el Paso 4.
  7. Haz clic en Create store. ¡Listo! Serás redirigido directamente al panel principal de administración (Shopify Admin).
2

Paso 2: Familiarización con los Elementos Clave del Shopify Admin

El Shopify Admin es el centro neurálgico donde gestionarás todo el negocio. En la barra superior encontrarás a Shopify Sidekick, el asistente de inteligencia artificial nativo capaz de asistirte en la configuración de la tienda, generación de copys de producto y resolución de dudas técnicas.

📦

Products & Variants

Las mercancías físicas o digitales que vendes. Una prenda como una remera de Lily se compone de opciones (Talla: S, M, L; Color: Azul, Verde). Cada combinación específica (ej. "Talla M en Color Azul") conforma una Variant con su propio inventario y SKU. Los productos también se vinculan a Locations (ubicaciones físicas de inventario), modelos de suscripción y Shopify Markets para localización internacional.

🗂️

Collections (Colecciones)

Agrupaciones de productos para facilitar el descubrimiento y aplicar descuentos:
• Automated (Smart) Collections: Se pueblan solas en tiempo real según condiciones (tags, precio, tipo o stock).
• Manual Collections: Curaduría estática donde seleccionas manualmente los ítems.

👥

Customers (Clientes)

El objeto Customer almacena nombres, contactos, historial de órdenes y direcciones. Permite crear cuentas de cliente para autocompletado en checkout y segmentación para campañas de retención.

🧾

Orders (Pedidos)

El eslabón relacional que conecta clientes con productos vendidos, gestionando el ciclo de vida del pago, autorización bancaria y estados de fulfillment (despacho).

Exploring and Extending Shopify’s Data Model

Aprende cómo Shopify modela las transacciones de e-commerce, explora los objetos fundamentales y de nicho (B2B / Retail), y domina la extensión del esquema de datos mediante Metafields y Metaobjects con prácticas reales.

Sección 1: Shopify’s Data Model & Core Ecommerce Concepts

El modelo de datos de Shopify está diseñado para respaldar todo el ciclo de vida de una transacción de comercio unificado. Para entender cómo interactúan los objetos en la base de datos, examinemos las 5 fases del flujo de compra:

1️⃣

1. Navegación en un Canal (Channel)

El cliente explora productos en un canal de venta (Online Store, POS o app móvil). Cada Product posee al menos una Variant por defecto y puede agruparse en Collections para facilitar el merchandising.

2️⃣

2. Carrito de Compras (Cart)

El carrito es específico del canal. En la tienda online se compone de Cart Line Items que registran la cantidad de cada variante, calculando el subtotal antes de impuestos, envíos o descuentos.

3️⃣

3. Inicio de Checkout

Flujo optimizado de 1 a 3 páginas donde el comprador ingresa su dirección de envío, método de despacho y cupones de descuento.

4️⃣

4. Pago y Creación de la Orden (Order)

La captura exitosa del pago crea la entidad Order y genera las páginas de confirmación (Thank You Page y Order Status Page) con número de pedido y fecha estimada de entrega.

5️⃣

5. Fulfillment y Despacho

La tienda prepara los productos para despacho. El inventario se actualiza automáticamente en tiempo real a través de todas las ubicaciones físicas (Locations) y se genera el código de seguimiento para el cliente.

Sección 3: Building Custom Data Objects (Metafields & Metaobjects)

Cuando los clientes demandan desplegar información especializada (guías de cuidado de plantas vivas, tablas de medidas de modelos, o certificaciones ecológicas), los Metafields y Metaobjects permiten extender el esquema relacional nativo sin requerir un CMS externo ni apps pesadas.

✨

Mayor Personalización & UX

Permite enriquecer las fichas de producto con información visualmente estructurada y relevante para aumentar la conversión.

🧩

Funcionalidad Extendida

Admite propiedades complejas como selectores de color hexadecimal, descargas de PDFs e integración con ERPs para lead times.

🔄

Disponibilidad Omnicanal

Accesibles tanto en el frontend (Liquid y Storefront API) como en el backend mediante la GraphQL Admin API para sincronización bidireccional.

Anatomía de los Metafields

Componente Propósito Ejemplo
Namespace Contenedor o categoría para agrupar campos con funciones similares. custom, specs, seo, model
Key Nombre identificador único del campo dentro del namespace. wearing_size, battery_life, care_pdf
Value El dato persistido fuertemente tipado. "Talla M", 14, #16a34a, referencia GID
🏷️

Tipos de Datos Estándar Soportados en Metafields

Color picker (swatches), Measurement (longitud, peso, ancho de manga), Reference (size charts, bundles, productos recomendados, metaobjects), Date & Time, Money, Text (single/multi-line), File (PDFs, imágenes en CDN), Number (integer/decimal), True/False (switches booleanos), JSON, Rating (estrellas/reseñas) y URL.

¿Qué son los Metaobjects?

Un Metaobject es una entidad de datos completa compuesta por múltiples campos estructurados. Posee dos elementos esenciales:

  • Definition (Definición): El esquema que declara la estructura (ej. Model Info con campos nombre, estatura, busto, cintura, caderas).
  • Entries (Entradas): Los registros o filas individuales de datos cargados (ej. Entrada para Jasmine, Entrada para Shakira).

9. Creación y Arquitectura de PLP (Product Listing Page)

Una Product Listing Page (PLP) o página de colección es el epicentro de la experiencia de compra en Shopify. Mientras que la PDP convierte al comprador decidido, la PLP es responsable de guiar el descubrimiento, estructurar la navegación por facetas (filtros) y mantener tiempos de carga ultrarrápidos (<1s First Contentful Paint). En este módulo aprenderás la arquitectura técnica detrás de las colecciones en Shopify Online Store 2.0 y construirás una PLP interactiva paso a paso utilizando los productos y metafields definidos en el catálogo.

Arquitectura de Archivos y Flujo de Renderizado en Temas OS 2.0

En los temas modernos de Shopify, la página de colección no es un archivo monolítico. Se desacopla en una jerarquía modular de Templates JSON, Secciones Liquid y Snippets reutilizables:

Archivo / Componente Ubicación en Tema Responsabilidad Técnica
templates/collection.json Templates Define el orden de secciones (banner, filtros, grid de productos, enriquecedores SEO) y almacena la configuración del Theme Editor.
sections/main-collection-product-grid.liquid Sections Controla el wrapper del grid, la paginación (paginate), el contenedor de facetas y la inyección del bucle for product in collection.products.
snippets/facets.liquid Snippets Renderiza el sistema de filtrado nativo mediante el objeto collection.filters (soporta filtros por precio, tags, disponibilidad y metafields).
snippets/card-product.liquid Snippets Componente atómico de tarjeta de producto. Renderiza thumbnail, badges, precio con descuento, color swatches y metafields de producto.
snippets/pagination.liquid Snippets Renderiza los enlaces accesibles de navegación entre páginas del catálogo respetando la estructura semántica SEO.
Regla de Oro de Rendimiento: Paginación Mandatoria

Shopify exige que cualquier iteración sobre collection.products esté envuelta en un tag {% paginate collection.products by N %} (máximo 50 productos por página). Intentar iterar sin paginar arrojará un error de compilación Liquid o limitará automáticamente a 50 ítems. La mejor práctica para tiendas enterprise es paginar entre 12 y 24 productos para optimizar el DOM Size y la métrica INP (Interaction to Next Paint).

Tags de Colección: Objetos Liquid, Filtrado por URLs y Buenas Prácticas

En Shopify, una Colección no posee un atributo directo de etiquetas propio en el panel de administración. En su lugar, el motor de Liquid sintetiza y expone las etiquetas de todos los productos asociados a dicha colección a través de los objetos collection.tags, collection.all_tags y el arreglo global current_tags.

Objeto Liquid Alcance (Scope) Comportamiento y Diferencias Clave
collection.all_tags Colección Completa Contiene todas las etiquetas únicas presentes en la totalidad de productos de la colección (hasta un límite de 1,000 tags), sin verse afectado por la paginación ni por los tags seleccionados actualmente.
collection.tags Contexto Filtrado / Vista Actual Devuelve las etiquetas disponibles en los productos resultantes de la página actual o del filtrado activo. Si hay un tag filtrando la URL, collection.tags solo contendrá los tags de los productos que coincidan.
current_tags Parámetros de URL Activos Arreglo de strings con los tags que el usuario está utilizando actualmente para filtrar la colección a través de la URL (ej: /collections/hoodies/algodon+oversize).

1. Enrutamiento Nativo de URLs por Tags en Shopify

Shopify permite filtrar colecciones mediante segmentos en el path de la URL sin necesidad de parámetros de consulta:

  • Filtro simple (1 Tag): /collections/running-shoes/maraton (Carga la colección filtrada por el tag "maraton").
  • Filtro compuesto (Múltiples Tags - AND lógico): /collections/running-shoes/maraton+impermeable (Carga productos que tengan ambos tags simultáneamente).

3. Patrón Prefijado (Grouped Tags) vs Storefront Filtering (OS 2.0)

Históricamente se utilizaban etiquetas con prefijos como color_negro, talla_xl o marca_nike para agrupar filtros en temas clásicos:

Tradeoffs de Arquitectura: ¿Tags o Metafields / Search & Discovery?

Aunque los tags siguen siendo muy útiles para reglas de Smart Collections (ej. automatizar colecciones de Rebajas) y badges en frontend (ej. tag "pre-order" o "outlet"), no se recomienda utilizarlos como sistema de filtros principal en tiendas modernas por las siguientes razones:

  • Sin control de tipo: Un error tipográfico en el Admin (Color: Rojo vs color_rojo) rompe la taxonomía.
  • Sin rangos de valores: Los tags no pueden filtrar rangos numéricos continuos (ej. precio mínimo/máximo o tallas numéricas).
  • Riesgo SEO de contenido duplicado: Cada combinación de /collections/handle/tag1+tag2 genera una URL que compite en rastreo si no se gestiona con etiquetas canonical y directivas noindex adecuadas.
  • Migración recomendada: Para filtrado por atributos complejos se debe utilizar collection.filters con Metafields de producto y la app Shopify Search & Discovery.

10. Anatomía y Auditoría de Componentes en un Tema Shopify

Antes de modificar, refactorizar o construir sobre un tema existente de Shopify (como Dawn, Horizon o un tema a medida), un desarrollador senior debe saber auditar qué componentes existen, cómo se comunican entre sí y dónde residen las fuentes de verdad. 1. Anatomía Estructural de un Tema en Shopify Online Store 2.0

Un tema de Shopify consta estrictamente de 7 directorios raíz obligatorios. Cada uno cumple una función específica dentro del ciclo de vida del renderizado:

Directorio Archivos Típicos Responsabilidad & Ciclo de Vida
layout/ theme.liquid, password.liquid El contenedor HTML global (<head>, scripts principales, <body>). Inyecta obligatoriamente {{ content_for_header }} en el head y {{ content_for_layout }} en el body.
templates/ index.json, product.json, collection.json, cart.json Plantillas JSON que definen qué secciones y en qué orden se renderizan en cada tipo de página. También almacenan los settings específicos de cada sección en esa página.
sections/ header.liquid, main-product.liquid, footer.liquid Componentes de bloque autónomos. Poseen su propio {% schema %} con configuración editable desde el Theme Editor, soporte para bloques reordenables (blocks) y presets.
snippets/ card-product.liquid, price.liquid, icon-cart.liquid Componentes atómicos reutilizables sin schema propio. Se invocan mediante {% render 'nombre-snippet', prop: valor %} con un scope de variables aislado.
assets/ theme.js, base.css, product-form.js Archivos estáticos (JavaScript, CSS, imágenes, SVG, fuentes). Se cargan en el frontend mediante el filtro de Liquid {{ 'archivo.js' | asset_url | script_tag }}.
config/ settings_schema.json, settings_data.json settings_schema.json define el panel de configuración global del tema (colores, tipografía, redes sociales). settings_data.json almacena los valores reales guardados por el comerciante.
locales/ es.json, en.default.json Archivos de traducción para internacionalización (i18n). Sus cadenas se consumen en Liquid con el filtro {{ 'general.cart.title' | t }}.

3. Secciones vs. Snippets: Reglas de Decisión Arquitectónica

Criterio Sections (sections/*.liquid) Snippets (snippets/*.liquid)
Schema Editable Sí: Contiene tag {% schema %} con controles para el Theme Editor. No: No puede tener schema propio. Recibe parámetros vía {% render %}.
Ámbito de Variables Tiene acceso al objeto global del template y sus propios section.settings. Aislado: No hereda variables locales salvo que se pasen explícitamente como argumentos.
Invocación Vía Template JSON o mediante {% section 'header' %}. Vía {% render 'card-product', product: item %}.
Uso recomendado Estructuras de layout completas, banners, grids, formularios principales. Microcomponentes reutilizables: botones, íconos, precios, badges, tarjetas.
Por qué `{% include %}` está PROHIBIDO en Temas Modernos

El tag antiguo {% include %} introducía variables en el scope global del padre, provocando colisiones de nombres de variables difíciles de depurar y degradando el rendimiento porque el compilador de Liquid no podía optimizar el AST (Abstract Syntax Tree). El tag moderno {% render %} aísla completamente el contexto, permitiendo compilación en paralelo y optimizaciones de caché en los edge servers de Shopify.

Módulo 13 • Seguridad & Gobernanza Enterprise

13. Role-Based Access Controls (RBAC) en Shopify Admin

En una organización en crecimiento, cada integrante del equipo desempeña responsabilidades específicas: desde especialistas en atención al cliente y cajeros en sucursales físicas, hasta desarrolladores frontend, redactores de contenido y directores financieros. Administrar los permisos usuario por usuario de manera manual no solo es ineficiente y propenso a errores humanos críticos, sino que representa una vulnerabilidad de seguridad inaceptable en entornos de nivel corporativo.

1. ¿Qué son los Role-Based Access Controls (RBAC)?

Role-Based Access Control (RBAC) es un mecanismo de autorización que asigna permisos de acceso al sistema a roles abstractos en lugar de a cuentas de usuario individuales. Los usuarios reciben uno o más roles según su función laboral, heredando automáticamente las capacidades y restricciones asociadas a dicho rol.

Dimensión Gestión Tradicional (Permisos 1 a 1) Control de Acceso por Roles (RBAC)
Asignación Se seleccionan casillas de permisos cuenta por cuenta al crear cada usuario. Se asocia el usuario a un rol preconfigurado (ej: Customer Support, Catalog Merchandiser).
Mantenimiento Si cambia una política, se deben editar decenas o cientos de usuarios manualmente. Se actualiza la definición del rol una sola vez y se propaga instantáneamente a todos los usuarios vinculados.
Escala Multi-tienda Permisos dispersos y desalineados entre tiendas regionales (ej. US, EU, MX, B2B). Los roles se gestionan a nivel de Organization Settings y se sincronizan entre múltiples tiendas.
Riesgo de Seguridad Alto riesgo de "Permission Creep" (usuarios que acumulan permisos obsoletos con el tiempo). Cumplimiento estricto del Principle of Least Privilege (PoLP) y auditoría centralizada.
💡
Principle of Least Privilege (Principio de Menor Privilegio): En arquitectura de seguridad, cada usuario, sistema o API token debe tener únicamente el conjunto mínimo indispensable de privilegios necesarios para realizar su tarea asignada, ni un permiso más. RBAC es la herramienta fundamental para implementar este principio en el ecosistema Shopify.

2. ¿Por qué implementar RBAC? Los 3 Pilares

🔄 1. Actualización Uniforme (Uniform Updating)

Cuando la empresa introduce una nueva funcionalidad (por ejemplo, gestión de borradores de pedidos o vista de metaobjetos de marketing), no necesitas ingresar a 50 perfiles de colaboradores. Modificas el rol una sola vez y todas las cuentas se actualizan en simultáneo de forma determinística.

⚡ 2. Eficiencia & Onboarding Acelerado

Reducción drástica del tiempo de alta y baja de colaboradores o agencias. Al contratar 10 nuevos agentes de atención al cliente, simplemente se les asigna el rol "Customer Service" al enviar la invitación por email, garantizando acceso inmediato y sin errores de configuración.

📈 3. Escalabilidad Multi-tienda & Gobernanza

En corporaciones con tiendas de expansión internacional, marcas múltiples o tiendas B2B mayoristas independientes bajo una misma organización de Shopify Plus, los roles se definen a nivel organizacional y pueden aplicarse granularmente a tiendas específicas según el alcance del usuario.

3. Creación y Configuración Paso a Paso de Roles

El flujo para configurar un nuevo rol en el panel de administración sigue una jerarquía clara:

1
Navegación al Menú de Roles

En el Shopify Admin, haz clic en el engranaje de Settings (esquina inferior izquierda) > Users and permissions (o Users) > pestaña Roles > botón Add role. (En organizaciones Shopify Plus: Organization settings > Users > Roles).

2
Nombre y Descripción Semántica del Rol

Asigna un nombre descriptivo y claro (ej. "Customer Service Specialist", "Copywriter & Content Editor", "Logistics & Fulfillment Team").

3
Selección de Permisos: Categoría vs. Permisos Granulares

Shopify ofrece dos niveles de control:

  • Checkbox de Categoría Principal: Al marcar la casilla de nivel superior (ej. Products), se conceden automáticamente todos los sub-permisos (Ver, Crear/Editar, Exportar, Eliminar).
  • Permisos Granulares: Puedes desglosar la categoría y seleccionar únicamente las capacidades permitidas (ej. Solo "View products" sin permitir crear ni modificar precios).
4
Asignación de Tiendas y Usuarios

Guarda el rol. Luego, al invitar o editar usuarios, selecciona el rol creado y especifica a qué tiendas de la organización tendrá acceso esa persona con dicho rol.

4. Permisos y Roles en Shopify Point of Sale (POS)

El personal de tiendas físicas suele requerir interacción directa con la app Shopify POS (en tablets o lectores de tarjetas), pero no necesita acceso al Shopify Admin web completo. Para ello, Shopify cuenta con un sistema de roles y PINs de seguridad específicos para POS:

🔢 Staff PINs & Bloqueo de Terminal

Cada miembro del personal de venta en salón utiliza un código PIN de 4 a 6 dígitos para autenticarse en el POS. Esto permite registrar exactamente qué vendedor cobró cada transacción y calcular comisiones o auditar el flujo de caja sin compartir credenciales.

🛡️ Permisos Sensibles de Caja y Manager Overrides

Puedes restringir acciones de alto impacto a cajeros estándar, tales como:

  • Descuentos manuales de línea o carrito (Custom Discounts)
  • Emisión de reembolsos físicos o devoluciones sin ticket
  • Apertura y cierre manual del cajón de dinero (Cash Drawer Tracking)
  • Override por PIN de Administrador/Manager en tiempo real

14. Creación y Gestión de Draft Orders en Shopify Admin

Los Draft Orders (Borradores de Pedido) son uno de los motores operativos más potentes y versátiles del back-office de Shopify. Permiten al equipo de soporte, ventas corporativas y desarrolladores crear órdenes manuales en nombre de clientes, sortear el flujo regular del storefront, cotizar ventas mayoristas (B2B), agregar productos personalizados fuera de catálogo y enviar enlaces de facturación directa con pasarela de pago protegida.

1. ¿Qué es un Draft Order y cuándo utilizarlo?

A diferencia de una orden estándar generada en el checkout público por el comprador, un Draft Order se origina en el panel de administración o mediante la DraftOrder API (GraphQL / REST). Permite estructurar una cotización antes de que se convierta en una venta formal (Order).

📞 1. Pedidos Telefónicos & Customer Support

Cuando un cliente experimenta dificultades técnicas en la pasarela o prefiere cerrar la compra por llamada/WhatsApp, el agente crea el borrador con los productos requeridos y le despacha una factura con link de pago seguro en 1 clic.

🏢 2. Ventas Mayoristas & B2B Invoicing

Para cotizaciones corporativas de alto volumen con términos de pago especiales (Net 30, Net 60), descuentos por volumen ad-hoc y tarifas de flete logístico negociadas que no existen en el storefront público.

✨ 3. Productos a Medida (Custom Items)

Permite cobrar por servicios especiales (ej. "Grabado láser conmemorativo", "Mano de obra técnica", "Garantía extendida") creando un ítem con precio y peso arbitrarios sin necesidad de crear un producto en el catálogo permanente.

🏷️ 4. Descuentos y Precios Excepcionales

Aplicación de descuentos de cortesía en porcentaje o monto fijo directamente en la línea de producto o sobre el total, sin tener que crear un código de cupón público que otros usuarios puedan descubrir.

2. Anatomía y Flujo Paso a Paso en el Shopify Admin

Para crear un borrador desde el panel de control:

1
Navegación a Orders > Drafts

En el menú lateral del Admin, abre la sección Orders y selecciona Drafts. Haz clic en el botón superior derecho Create order (o Crear borrador de pedido).

2
Selección de Productos vs. Custom Items

Puedes combinar dos tipos de elementos en el pedido:

  • Productos del catálogo existente: Se buscan por título o SKU y descuentan inventario una vez confirmada la orden o al presionar "Reserve items".
  • Add custom item (Ítem personalizado): Define un nombre, precio unitario, cantidad, si requiere envío y peso específico para envíos. Ideal para presupuestos a medida.
3
Asignación de Cliente, Envío e Impuestos

En el panel derecho, vincula un perfil de cliente existente o crea uno nuevo con su correo y teléfono. Shopify calculará automáticamente las tarifas de envío e impuestos según la dirección de entrega, o te permitirá ingresar una tarifa de flete manual personalizada (ej. "Flete Express Bodega $0 - Cortesía").

4
Envío de Factura (Send Invoice) o Cobro Inmediato

Una vez armado el borrador, cuentas con 3 caminos para procesar el pago:

  • Send invoice (Enviar factura): Despacha un correo electrónico corporativo con un botón "Completar tu compra" que redirige al cliente al checkout oficial con los datos pre-cargados.
  • Collect payment (Cobrar con tarjeta): El agente ingresa los datos de tarjeta de crédito suministrados por teléfono de forma segura.
  • Mark as paid (Marcar como pagado): Para órdenes abonadas por transferencia bancaria directa, efectivo contra entrega o cheque.
