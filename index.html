1. Modelo de Datos de Productos en Shopify

Antes de escribir una sola línea de Liquid o realizar llamadas a la Admin API, es imprescindible comprender cómo Shopify normaliza y almacena sus entidades de catálogo en su base de datos relacional subyacente.

Arquitectura del Producto: Products vs. Variants

En Shopify, la entidad Product no es un artículo vendible directamente por sí mismo en el checkout; actúa como un contenedor padre o paraguas conceptual que agrupa metadatos globales (título, descripción HTML, proveedor, tipo de producto, etiquetas y lista de imágenes generales).

La entidad ProductVariant representa la unidad de inventario comercializable real (relación 1 a N). Cada variante posee su propio precio, precio de comparación (compare_at_price), SKU, código de barras (barcode), peso físico y puntero directo al inventario.

Estructura Relacional del Catálogo (1:N)
Product (Contenedor Padre) Entidad Global
  • id: ID (GID)
  • title: String
  • handle: String (Slug URL)
  • vendor: String
  • options: Array<ProductOption>
  • media: Array<Media>
ProductVariant (Item Vendible en Checkout) 1 a N Variantes
  • id: ID (GID)
  • sku: String
  • price: Money
  • inventory_item_id: ID
  • selected_options: [ {name, value} ]
  • requires_shipping: Boolean

Opciones y Valores (Options & Values)

Las opciones definen las dimensiones de variación del producto (por ejemplo: Talla, Color, Material). En Liquid se accede mediante el objeto iterativo product.options_with_values.

⚠️

Restricción Nativa: 3 Opciones / 100 Variantes

Shopify impone un límite estricto de máximo 3 opciones por producto y un total combinado de 100 variantes (ej: 4 tallas x 5 colores x 6 materiales = 120 combinaciones, lo cual excedería el límite). Solución de Arquitectura: Para catálogos complejos, se implementa arquitectura de "Productos Vinculados" (Linked Products) conectados vía Metafields de referencia, o personalizaciones vía Line Item Properties.

Colecciones: Manuales vs. Automatizadas (Smart Collections)

Característica Colecciones Manuales (CustomCollections) Colecciones Automatizadas (SmartCollections)
Mecanismo de Inclusión Asignación estática 1 por 1 por el administrador. Reglas dinámicas booleanas (AND / OR).
Condiciones Soportadas No aplica (lista explícita). Tags, Product Type, Vendor, Price, Compare Price, Inventory Stock.
Mantenimiento Operativo Alto. Requiere intervención manual con nuevos SKUs. Bajo / Automático en tiempo real al indexar productos.
Uso Recomendado Curaduría editorial, promociones especiales, lookbooks. Catálogos masivos por categorías, marcas o estado de inventario.

Creación de Productos vía Código: GraphQL vs. REST Admin API

Shopify recomienda GraphQL Admin API como estándar exclusivo para desarrollos modernos debido al costo de consulta medido por complejidad (query cost) en lugar de rate limits ciegos, y a la capacidad de crear productos y variantes anidadas en un solo llamado atómico.

# Creación atómica de Producto con Variantes, SKU e Inventario
mutation CreateCompleteProduct($input: ProductInput!) {
  productCreate(input: $input) {
    product {
      id
      title
      handle
      status
      variants(first: 5) {
        nodes {
          id
          sku
          price
          inventoryItem {
            id
            tracked
          }
        }
      }
    }
    userErrors {
      field
      message
    }
  }
}

Módulo 02

2. Dominio Total de Metafields y Metaobjects

Los Metafields permiten extender el esquema de datos nativo asociando pares clave-valor fuertemente tipados a productos, variantes, clientes o pedidos. Los Metaobjects son entidades completas y reutilizables compuestas por múltiples campos, equivalentes a tablas relacionales personalizadas en Shopify.

Tipos de Datos en Metafields

📄

Texto y Primitivos

single_line_text_field, multi_line_text_field, number_integer, number_decimal, boolean, date y color.

🔗

Referencias (References)

file_reference (PDFs, videos, imágenes en CDN), product_reference, page_reference y metaobject_reference.

📚

Listas (Lists)

Array tipado: list.single_line_text_field o list.file_reference para galerías de demostración y listas de características.

⚙️

Estructuras JSON

json: Permite persistir estructuras anidadas arbitrarias cuando se requiere flexibilidad no soportada por tipos estándar.

Metafields en Liquid: Sintaxis y Filtros

En Liquid, el acceso canónico se realiza a través de la notación de objeto {{ resource.metafields.namespace.key.value }}. Regla de oro: Siempre incluir la propiedad .value para desempaquetar el objeto tipado subyacente.

Metaobjects: Modelado Reutilizable y Páginas Dinámicas

Un Metaobject es un registro estructurado con una definición formal (Schema). Son ideales para entidades que se repiten a lo largo de múltiples productos, como tablas de medidas (Size Charts), perfiles de autores/diseñadores o guías de cuidado y garantía.

Conexión con el Theme Editor (Dynamic Sources)

En la arquitectura Online Store 2.0 (OS 2.0), los esquemas de secciones y bloques (`schema JSON`) permiten definir configuraciones que se pueden conectar dinámicamente con Metafields y Metaobjects sin alterar código.

Arquitectura sin Código para Clientes

Al vincular Metafields como Dynamic Sources en el Theme Editor, los editores y gestores de catálogo de la tienda pueden cambiar especificaciones o asociar tablas de cuidado desde la interfaz visual nativa de Shopify, garantizando un acoplamiento limpio entre contenido y diseño.

3. Filtrado y Búsqueda con Datos Personalizados

Las tiendas enterprise demandan sistemas de filtrado por facetas (Facet Filtering) avanzados, como filtrar colecciones por rango de frecuencia, tipo de material o compatibilidad, alimentados directamente por Metafields.

Shopify Search & Discovery App

La aplicación oficial Shopify Search & Discovery permite activar filtros nativos basados en:

  • Disponibilidad de stock (`filter.v.availability`).
  • Rango de precios (`filter.v.price.gte` / `filter.v.price.lte`).
  • Opciones de producto (`filter.v.option.color`).
  • Metafields personalizados (`filter.p.m.custom.material` o `filter.p.m.custom.connectivity`).

Storefront Filtering API & AJAX Rendering

Para crear una experiencia de filtrado instantánea sin recargar la página completa, consumimos la Shopify Section Rendering API pasando los parámetros de filtro mediante JavaScript (Fetch).

JavaScript (ES6+) assets/collection-filters.js 
// Implementación de Facet Filter reactivo con Section Rendering API
class CollectionFilters {
  constructor(formElement, gridContainerId) {
    this.form = formElement;
    this.gridContainer = document.getElementById(gridContainerId);
    this.bindEvents();
  }

  bindEvents() {
    this.form.addEventListener('change', () => this.applyFilters());
  }

  async applyFilters() {
    const formData = new FormData(this.form);
    const params = new URLSearchParams(formData);
    
    // Indicamos a Shopify que solo re-renderice la sección de grilla de productos
    params.set('section_id', 'main-collection-product-grid');
    
    // Actualizamos URL en el navegador sin recargar
    window.history.pushState({}, '', `${window.location.pathname}?${params.toString()}`);

    try {
      this.gridContainer.classList.add('is-loading');
      
      const response = await fetch(`${window.location.pathname}?${params.toString()}`);
      const htmlText = await response.text();
      
      const parser = new DOMParser();
      const doc = parser.parseFromString(htmlText, 'text/html');
      const newGridContent = doc.getElementById('main-collection-product-grid');

      if (newGridContent) {
        this.gridContainer.innerHTML = newGridContent.innerHTML;
      }
    } catch (error) {
      console.error('Error al aplicar filtros de colección:', error);
    } finally {
      this.gridContainer.classList.remove('is-loading');
    }
  }
}

Lab: Build a dev store with product data and simulate a transaction

Construcción de una tienda de desarrollo para indumentaria ("Stylish Stitches"), exploración del Shopify Admin, importación masiva de catálogo y simulación de transacciones con pasarela de prueba.

👗

Escenario de Cliente: "Stylish Stitches"

Un negocio de indumentaria y moda de autor llamado "Stylish Stitches", propiedad de la diseñadora Lily, está iniciando su transformación digital para expandir su alcance mediante una tienda online en Shopify. Ante el desafío de llevar sus prendas de alta confección al mundo virtual, Lily recurre a vos para construir y configurar su tienda desde las bases.

Nota de arquitectura: Nunca utilices una tienda real de producción para estas actividades prácticas. Crearemos una Development Store (Tienda de Desarrollo) en Shopify Partners para ejecutar personalizaciones de tema, scripts Liquid y pruebas backend sin costos ni riesgos.

1

Paso 1: Registro en Shopify Partners y Creación de la Tienda de Desarrollo

Sigue estos pasos en el portal de partners de Shopify:

  1. Crea una cuenta en Shopify Partners (si aún no posees una).
  2. Haz clic en tu nombre en la esquina superior derecha y selecciona Dev Dashboard.
  3. En el menú lateral izquierdo, haz clic en Dev stores (Tiendas de desarrollo).
  4. Haz clic en el botón Create dev store (Crear tienda de desarrollo).
  5. Asigna un nombre a tu tienda (por ejemplo: stylish-stitches-lab) y selecciona el propósito de la tienda (Build a new store for a client).
  6. IMPORTANTE: No selecciones "Generate test data for store". Dejaremos la tienda limpia para importar nuestro propio catálogo de indumentaria en el Paso 4.
  7. Haz clic en Create store. ¡Listo! Serás redirigido directamente al panel principal de administración (Shopify Admin).
2

Paso 2: Familiarización con los Elementos Clave del Shopify Admin

El Shopify Admin es el centro neurálgico donde gestionarás todo el negocio. En la barra superior encontrarás a Shopify Sidekick, el asistente de inteligencia artificial nativo capaz de asistirte en la configuración de la tienda, generación de copys de producto y resolución de dudas técnicas.

📦

Products & Variants

Las mercancías físicas o digitales que vendes. Una prenda como una remera de Lily se compone de opciones (Talla: S, M, L; Color: Azul, Verde). Cada combinación específica (ej. "Talla M en Color Azul") conforma una Variant con su propio inventario y SKU. Los productos también se vinculan a Locations (ubicaciones físicas de inventario), modelos de suscripción y Shopify Markets para localización internacional.

🗂️

Collections (Colecciones)

Agrupaciones de productos para facilitar el descubrimiento y aplicar descuentos:
• Automated (Smart) Collections: Se pueblan solas en tiempo real según condiciones (tags, precio, tipo o stock).
• Manual Collections: Curaduría estática donde seleccionas manualmente los ítems.

👥

Customers (Clientes)

El objeto Customer almacena nombres, contactos, historial de órdenes y direcciones. Permite crear cuentas de cliente para autocompletado en checkout y segmentación para campañas de retención.

🧾

Orders (Pedidos)

El eslabón relacional que conecta clientes con productos vendidos, gestionando el ciclo de vida del pago, autorización bancaria y estados de fulfillment (despacho).

3

Paso 3: Explorando el Resto del Admin & Unified Commerce

Debajo de las entidades de e-commerce principales, dispones de módulos clave:

  • Content (Contenido): Repositorio centralizado de archivos multimedia en CDN y el gestor de Metaobjects.
  • Discounts (Descuentos): Reglas de monto fijo, porcentaje, "Compra X y lleva Y" (BXGY), envíos gratis y reglas avanzadas programadas con Shopify Functions.
  • Finance, Analytics & Marketing: Reportes de margen bruto, valor promedio del pedido (AOV), embudos de conversión y sesiones web.
  • Sales Channels (Comercio Unificado):
    • Online Store: Gestión de temas Liquid, páginas estáticas y blogs.
    • Point of Sale (POS): Para ventas presenciales en tiendas físicas, ferias o pop-ups de moda.
    • Shop App: Canal móvil con más de 100 millones de compradores activos con checkout acelerado (Shop Pay).
  • Settings (Configuración): Configuración de monedas, impuestos, pasarelas de pago, shipping zones y permisos.
4

Paso 4: Importar Datos de Indumentaria de Muestra (Apparel CSV)

Démosle vida a la tienda de Lily cargando el catálogo de prueba:

  1. Descarga el archivo oficial de prueba: apparel.csv en GitHub de Shopify Partners.
  2. En el Shopify Admin, ve a Products y haz clic en el botón superior Import.
  3. Sube el archivo apparel.csv y confirma la importación.

Módulo Avanzado • Data Architecture

Exploring and Extending Shopify’s Data Model

Aprende cómo Shopify modela las transacciones de e-commerce, explora los objetos fundamentales y de nicho (B2B / Retail), y domina la extensión del esquema de datos mediante Metafields y Metaobjects con prácticas reales.

Sección 1: Shopify’s Data Model & Core Ecommerce Concepts

El modelo de datos de Shopify está diseñado para respaldar todo el ciclo de vida de una transacción de comercio unificado. Para entender cómo interactúan los objetos en la base de datos, examinemos las 5 fases del flujo de compra:

1️⃣

1. Navegación en un Canal (Channel)

El cliente explora productos en un canal de venta (Online Store, POS o app móvil). Cada Product posee al menos una Variant por defecto y puede agruparse en Collections para facilitar el merchandising.

2️⃣

2. Carrito de Compras (Cart)

El carrito es específico del canal. En la tienda online se compone de Cart Line Items que registran la cantidad de cada variante, calculando el subtotal antes de impuestos, envíos o descuentos.

3️⃣

3. Inicio de Checkout

Flujo optimizado de 1 a 3 páginas donde el comprador ingresa su dirección de envío, método de despacho y cupones de descuento.

4️⃣

4. Pago y Creación de la Orden (Order)

La captura exitosa del pago crea la entidad Order y genera las páginas de confirmación (Thank You Page y Order Status Page) con número de pedido y fecha estimada de entrega.

5️⃣

5. Fulfillment y Despacho

La tienda prepara los productos para despacho. El inventario se actualiza automáticamente en tiempo real a través de todas las ubicaciones físicas (Locations) y se genera el código de seguimiento para el cliente.

Objetos Fundamentales de E-Commerce en Shopify

Objeto Descripción del Objeto Recursos Conectados en el Modelo
Products Artículos individuales o digitales disponibles para la venta. Collections, Locations, ProductVariants
Collections Agrupaciones de productos para navegación y merchandising. Products
Customers Compradores registrados o que realizaron pedidos. Orders, Gift cards, Companies
Companies (B2B) Entidades corporativas asociadas a clientes para compras B2B al por mayor. Customers, CompanyLocations
Locations Ubicaciones físicas donde se almacena stock (almacenes, tiendas minoristas). Products, InventoryLevels
Orders Transacciones completadas con detalles de productos y pagos. Products, Locations, Customers, Markets, Companies
Discounts Promociones y reducciones de precio para productos o colecciones. Products, Collections
Markets Segmentos geográficos con reglas de precios, divisas e idiomas locales. Prices, Catalogs, Orders
Fulfillment orders Tareas y etapas necesarias para empaquetar y despachar partes de una orden. Orders, FulfillmentServices
Fulfillment services Proveedores logísticos externos (3PL) para almacenamiento y envío. Products, FulfillmentOrders
Gift cards Emisión y canje de crédito de tienda en formato de tarjetas de regalo. Customers, Orders

Para clientes con requerimientos corporativos (B2B) o tiendas físicas con retiro en sucursal (Retail), Shopify dispone de objetos especializados en Liquid y GraphQL:

  • customer.current_company: Empresa B2B activa durante la sesión del comprador.
  • store_availability: Objeto que consulta el inventario local para retiro en tienda física (Pickup in store).

Sección 3: Building Custom Data Objects (Metafields & Metaobjects)

Cuando los clientes demandan desplegar información especializada (guías de cuidado de plantas vivas, tablas de medidas de modelos, o certificaciones ecológicas), los Metafields y Metaobjects permiten extender el esquema relacional nativo sin requerir un CMS externo ni apps pesadas.

✨

Mayor Personalización & UX

Permite enriquecer las fichas de producto con información visualmente estructurada y relevante para aumentar la conversión.

🧩

Funcionalidad Extendida

Admite propiedades complejas como selectores de color hexadecimal, descargas de PDFs e integración con ERPs para lead times.

🔄

Disponibilidad Omnicanal

Accesibles tanto en el frontend (Liquid y Storefront API) como en el backend mediante la GraphQL Admin API para sincronización bidireccional.

Anatomía de los Metafields

Componente Propósito Ejemplo
Namespace Contenedor o categoría para agrupar campos con funciones similares. custom, specs, seo, model
Key Nombre identificador único del campo dentro del namespace. wearing_size, battery_life, care_pdf
Value El dato persistido fuertemente tipado. "Talla M", 14, #16a34a, referencia GID
🏷️

Tipos de Datos Estándar Soportados en Metafields

Color picker (swatches), Measurement (longitud, peso, ancho de manga), Reference (size charts, bundles, productos recomendados, metaobjects), Date & Time, Money, Text (single/multi-line), File (PDFs, imágenes en CDN), Number (integer/decimal), True/False (switches booleanos), JSON, Rating (estrellas/reseñas) y URL.

¿Qué son los Metaobjects?

Un Metaobject es una entidad de datos completa compuesta por múltiples campos estructurados. Posee dos elementos esenciales:

  • Definition (Definición): El esquema que declara la estructura (ej. Model Info con campos nombre, estatura, busto, cintura, caderas).
  • Entries (Entradas): Los registros o filas individuales de datos cargados (ej. Entrada para Jasmine, Entrada para Shakira).

Módulo 09 • Lab Práctico

9. Creación y Arquitectura de PLP (Product Listing Page)

Una Product Listing Page (PLP) o página de colección es el epicentro de la experiencia de compra en Shopify. Mientras que la PDP convierte al comprador decidido, la PLP es responsable de guiar el descubrimiento, estructurar la navegación por facetas (filtros) y mantener tiempos de carga ultrarrápidos (<1s First Contentful Paint). En este módulo aprenderás la arquitectura técnica detrás de las colecciones en Shopify Online Store 2.0 y construirás una PLP interactiva paso a paso utilizando los productos y metafields definidos en el catálogo.

Arquitectura de Archivos y Flujo de Renderizado en Temas OS 2.0

En los temas modernos de Shopify, la página de colección no es un archivo monolítico. Se desacopla en una jerarquía modular de Templates JSON, Secciones Liquid y Snippets reutilizables:

Archivo / Componente Ubicación en Tema Responsabilidad Técnica
templates/collection.json Templates Define el orden de secciones (banner, filtros, grid de productos, enriquecedores SEO) y almacena la configuración del Theme Editor.
sections/main-collection-product-grid.liquid Sections Controla el wrapper del grid, la paginación (paginate), el contenedor de facetas y la inyección del bucle for product in collection.products.
snippets/facets.liquid Snippets Renderiza el sistema de filtrado nativo mediante el objeto collection.filters (soporta filtros por precio, tags, disponibilidad y metafields).
snippets/card-product.liquid Snippets Componente atómico de tarjeta de producto. Renderiza thumbnail, badges, precio con descuento, color swatches y metafields de producto.
snippets/pagination.liquid Snippets Renderiza los enlaces accesibles de navegación entre páginas del catálogo respetando la estructura semántica SEO.
Regla de Oro de Rendimiento: Paginación Mandatoria

Shopify exige que cualquier iteración sobre collection.products esté envuelta en un tag {% paginate collection.products by N %} (máximo 50 productos por página). Intentar iterar sin paginar arrojará un error de compilación Liquid o limitará automáticamente a 50 ítems. La mejor práctica para tiendas enterprise es paginar entre 12 y 24 productos para optimizar el DOM Size y la métrica INP (Interaction to Next Paint).

Paso 1: Configurar la Colección en Shopify Admin (Smart vs Manual)

Una colección puede crearse de dos formas:

  • Manual: Curas individualmente cada producto añadiéndolo a mano. Ideal para colecciones de autor o "Lo más vendido del mes".
  • Automática (Smart Collection): Creas condiciones lógicas como Product tag is equal to "sustainable" o Product type is equal to "Wearables". Cualquier producto nuevo que coincida se indexa automáticamente.
Colección Automática vía Admin GraphQL API 
mutation CreateSmartCollection {
  collectionCreate(input: {
    title: "Colección Sustentable & Tech",
    descriptionHtml: "<p>Prendas y gadgets con certificación ecológica.</p>",
    ruleSet: {
      appliedDisjunctively: false,
      rules: [
        {
          column: TAG,
          relation: EQUALS,
          condition: "eco-friendly"
        },
        {
          column: VARIANT_PRICE,
          relation: GREATER_THAN,
          condition: "0"
        }
      ]
    }
  }) {
    collection {
      id
      handle
      title
    }
    userErrors {
      field
      message
    }
  }
}

query GetCollectionWithFacetsAndMetafields($handle: String!, $filters: [ProductFilter!]) {
  collection(handle: $handle) {
    id
    title
    description
    products(first: 12, filters: $filters, sortKey: PRICE, reverse: false) {
      pageInfo {
        hasNextPage
        hasPreviousPage
      }
      filters {
        id
        label
        type
        values {
          id
          label
          count
          input
        }
      }
      edges {
        node {
          id
          title
          handle
          vendor
          productType
          featuredImage {
            url
            altText
            width
            height
          }
          priceRange {
            minVariantPrice {
              amount
              currencyCode
            }
          }
          # Metafields en la Storefront API
          sustainabilityScore: metafield(namespace: "custom", key: "sustainability_score") {
            value
            type
          }
          materialComposition: metafield(namespace: "custom", key: "material") {
